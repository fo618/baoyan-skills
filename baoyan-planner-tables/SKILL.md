# 保研规划 PPT 生成 Skill

为保研规划师生成学员专属的规划表。**唯一交付形态：把两张表（学员信息 / 院校定档）以原生 PPT 表格写进 PPT**（用户给 pptx 就用用户的；没给就用内置【你的称呼】模板，26 页）。**Excel 已全面下线：不再生成、不再交付**，只交 PPT + 数据源 JSON。所有表使用统一的深红主题排版。

## 🔴 快速导航（30 秒上手，先看这里）

**第一步：判断输入是什么，走哪条线。**

| 输入 | 走哪条 | 主流程入口 |
|---|---|---|
| 学员背景（XX大学XX专业，年级 / 绩点 / 英语 / 竞赛） | **形态 A：PPT 规划表**（默认） | 「工作流程」→「输出物」→「PPT 投放流程」 |
| 院校推免政策文件（PDF / 网页原文） | **形态 C：政策解读 HTML** | 「形态 C：政策解读 HTML」整节 |
| 两者都有 | 先 C 后 A，两份一起交付 | — |

**形态 A 主流程只有 5 步**（执行细节见「工作流程」）：

1. **核实事实**——WebSearch 查院校层次标签、推免硬条件、招生培养变动（不可跳过）
2. **写数据**——按 `assets/sample_data.json` 结构写 `student_data_*.json`（改这个文件即可重跑）
3. **`--dry-run` 预检**——看字号/表高/版心，两张表都 ≥10pt 且无「⚠溢出」
4. **出成品 + 抓政策**——PPT 自动落**桌面**；同步抓学员本校+本院推免方案 HTML 落**桌面**
5. **交付**——`present_files` 展示 PPT + 政策 HTML + JSON，回复写明文件绝对路径

> ⚠️ **动笔前必读一次「铁律」整节**（20 条硬约束 + 19a~19k 各类学员特殊口径），违反即返工；交付前对照「质量自检」清单逐项打勾。

> 🚫 **已下线功能（不要再生成）**：主线任务表 · Excel/xlsx（`generate_tables.py`）· 全国硕士研究生招生工作管理规定（`fetch_yanzhaowang_policy.py`）。
> 三者的**历史存档与恢复方法**统一收在文末「已下线与回溯」一节，正文不再重复解释。

同事上手看 `README.md`（安装、触发用语、参数速查、文案长度标准）。

## 🧯 失败模式速查表（遇到就查这里）

> 按「触发条件 → 一线修复 → 仍失败兜底」三段式。下面全是**实测踩过的坑**，不要重新踩。

| 触发条件（症状） | 一线修复 | 仍失败兜底 |
|---|---|---|
| JSON 交给脚本报 `Expecting ',' delimiter` | 中文引号一律改「」/全角，不用 ASCII `"`（铁律 16） | 用 `json.dumps(obj, ensure_ascii=False)` 重新序列化写出 |
| WebFetch 抓 `.pdf` 返回 `fetch failed` | `curl -sL -k -o x.pdf "<url>"` 下载 + `pypdf` 抽文本（铁律 6） | 去官网 / 学信网找网页版原文，或 OCR |
| 研招网脚本提示"未找到 taskId" | 多为站点限流：稍等重试；确认脚本走的是 curl 不是 urllib | 加 `--url <正文页URL>` 手动指定，或换时段再跑 |
| 院校政策 HTML 只有 ~3KB / 正文 1 行 | 这是**跳转链接不是正文**：跟到学院官网抓 `v_news_content` / `vsb_content` 容器（铁律 19i） | 容器里只有 `showVsbpdfIframe` → 拼绝对 URL 下内嵌 PDF，`pypdf` 抽全文 |
| 学院官网附件带图形验证码（下回一个 ~3756 字节的伪装 HTML） | **别硬下**：改用网页正文里已写明的条款与文件名（铁律 19e） | 表里注明"以学院当年公示为准"，不写未拿到的原件内容 |
| 研招网**院系条目**指向的教务处汇总页已失效（返回 HTTP 410「无效的文章参数」，或 301 到 "htm file not found"） | **改用「校级方案 ＋ 学院待确认清单」两段式交付**：硬门槛基本全在校级原文里（读透即可写表 1），把只有学院才能拍板的项（权重、加分细则、分专业名额）单列待确认，**不留 3KB 空壳**（铁律 19m） | 去学院官网栏目页再扫一轮（`/cs/1007/list.htm` 这类）；仍无则如实说明并指向学院教学办，不要编条款 |
| `--dry-run` 打印「⚠溢出」 | 回去精简 JSON 文案（删字 / 换校名简称），**不要压字号** | `--max-font 11`，或把长内容拆进 `ppt_tables` 覆盖块 |
| `--dry-run` 看到「第 N 行 direction 超限」 | 回 `ppt_tables.school_tiers[N-1]` 补 ≤20 字短 direction（铁律 19c） | 校名一并用简称（≤12 字） |
| 院校层次自检中止并打印明细 | 按明细改 `school_tiers`（换校或调档）；**默认不许 `--force`** | 确属学科实力覆盖（A+ 行业校）→ `fit` 写明理由后再 `--force` |
| 自动匹配不到 PPT 里的表页 | `--slides 2,3` 手动指定页码（顺序：学员信息 / 院校定档） | `--mode append` 追加新页 |
| 输出比预期少页（空内容页被误删） | `--keep-empty-pages` 保守处理 | 检查那页是否真的只有标题没内容 |
| 旧字段 `student_profile` / `main_tasks` 命中报错 | 按 `assets/sample_data.json` 结构重写 JSON | 参见「数据源字段」 |
| PyMuPDF 报 `object of type 'float' has no len()` | 已知 API 变更，脚本已绕开（改用逐行 `insert_text`） | 改这块别再依赖 `insert_textbox` 的返回值语义 |

## 铁律（每次调用前先读，违反即返工）

1. **院校层次硬约束**：定档院校只能是 985 / 211 / 双一流，或中国科学院大学及中科院各研究所；双非、四非一律不进任何档位——**包括学员本校**；保底档最低 211。
   - **唯一例外**：`overseas: true` 的**海外兜底行**（如中外合作办学 4+1 硕士、双学位直升），且必须同时满足三个条件——学员确有中外合作/双学位/留学项目；该行只能出现在**保底档**；且必须是**全表最后一行**。
2. **每档至少 2 所，推荐 4 所**（冲刺 4 + 稳妥 4 + 保底 4 = 12 行）。定档表首列「梯度」同档位必须**纵向合并**成一格。
3. **对齐铁律**：表头行居中；长文本单元格（内容/方向/优势/录取条件/成绩/英语/竞赛/科研/其他）一律"横向靠左 + 纵向居中"；短标签列（梯度 / 时间）"横向居中 + 纵向居中"。
4. **只交付 PPT + JSON**（主线任务表与 Excel 均已下线）：不生成主线任务表（`main_timeline` 字段保留仅为兼容旧 JSON）、不运行 `generate_tables.py`、不产出 xlsx。需求里出现"Excel / 出个表"字样时也默认走 PPT，**只有用户明确点名要 Excel** 才恢复 `generate_tables.py`。历史存档见文末「已下线与回溯」。
5. **开箱即截图**：生成即可整表截图或导出 PDF，绝不让用户再手动调行高列宽。
6. **先查事实再动笔**：学员院校/学院的最新招生口径、办学模式、推免政策与保研率必须先用 WebSearch 核实，不得凭印象写通用内容。
   - **抓政策原文 PDF 的稳法（2026-09-23 实测）**：WebFetch 对 `.pdf` 经常直接 `fetch failed`，别反复重试——改用 `curl -sL -k -o x.pdf "<url>"` 下载，再用 `pypdf`（venv 里已装）`PdfReader(...).extract_text()` 抽文本，然后 `txt.find("第九条")` 定位条款逐条照抄。这样拿到的才是 100% 可验真的硬门槛（分数、占比、截止日、条款号），比二手解读稿可靠得多。
7. **不追问、直接推断**（**唯一例外见「🛑 检查点」**）：保研规划师给的学员信息通常极简（年级 + 院校 + 专业 + 方向，例"学生大一，26中传中日双播方向，国际传播"，其中"26"=2026 级），绩点/英语/竞赛常缺省。缺省项按该院校该专业的通用情况推断，并在表内如实标注"尚未启动/尚未考试"，不要反复追问。**但「校名/专业对不上」「跨保资格存疑」这两类必须先按「🛑 检查点」确认，不算"反复追问"。**
8. **字数只求简洁**：这是用户 2026-09-17 的硬要求——**能少不能多**。所有单元格写"动宾短语 / 短语堆叠"，不写完整长句；同一个意思只出现一次，不重复修饰。
9. **可复现**：定制内容必须落在工作目录的 JSON（`student_data_*.json`）里，学员信息更新时改 JSON 重跑脚本即可，不要只在 PPT 里改。
10. **PPT 投放用原生表格**：往 PPT 里放表时**禁止贴 Excel 截图**，一律用 `scripts/build_ppt_slides.py` 写原生 PowerPoint 表格——可编辑、可按版面比例自适应、字号自动精算、首列自动纵向合并。
11. **封面每回同步学员信息**：出 PPT 时第 1 页封面的院校名和专业名必须换成本次学员的信息，不得沿用上一份学员的（数据源见「封面自动改写」）。脚本已默认执行，检查输出里有没有 `封面改写` 两行即可确认。
12. **定档梯度按"实际录取难度"排序**（学科评估 + 区位 + 招生规模 + 软科位次综合判断），`rank` 字段（软科位次）用于自检梯度：**冲刺档均位次应优于保底档**。软科综合位次是重要参考但不机械排序——同济环境 A+ 放在冲刺、中山环境 B+ 放在稳妥是合理的，只要 `fit` 里写清理由。写数据前先用 WebSearch 核实当年软科排名。
13. **一次只出两张表，页数取决于你的模板**：参考版式《【你的称呼】保研规划》是 16:9、**26 页**——学员信息在第 2 页、院校定档在第 3 页，两页刚好用满（没有多余空内容页可删，输出就是 26 页）。**换成你自己的模板后页数可能不同，属正常**（脚本会自动清掉没投表格的空内容页，不想删加 `--keep-empty-pages`）。原版已删掉的页（旧版重复页、「各阶段重点任务分析」、「前辈寄语 / Q&A」、「主线任务分析」）不要再加回来。
14. **形态 C（政策解读 HTML）"原文 / 解读必须分家"**：凡是"政策原文要求""分值""否决情形""流程"这类栏目，必须**逐条对应政策条款，不得臆造、不得四舍五入**；凡是"白话解读""难度""性价比""战略含义""行动路线图"，一律**在页脚声明为非官方口径的分析意见**。二者混写 = 返工。
15. **形态 C 必须留下"待确认清单"**：政策里凡写"由各学院自行制定 / 参照当年发布的榜单 / 按教育部当年下达"的，一律不能写成确定结论，必须进 `todos` 模块并写明咨询对象（学院教学办 / 当年推免办法文件）。宁可多列，不要替学院拍板。
16. **JSON 里禁止出现 ASCII 直引号**：写入 `student_data_*.json` / `policy_data_*.json` 时，中文内容里的引号一律用「」或全角引号，绝不能出现 `"`，否则 `json.load` 会直接报 `Expecting ',' delimiter` 并中止生成（2026-09-19 上海应用技术大学学员实测踩到）。写完后先跑一次 `python -c "import json,io; json.load(io.open(文件,encoding='utf-8'))"` 再交给生成脚本。
17. **档位层次硬约束（2026-09-19 用户定版，脚本已强制自检）**：
    - **冲刺档＝必须全部中上 985，优先 C9 / 华五**（清北复交人浙南 + 中科大、哈工大、西交等）；非 985 一律不得进冲刺档（含行业顶尖 211）。中国科学院大学及中科院各研究所视同顶尖 985，可用于任何档位。
    - **稳妥档＝大部分是 985**（4 所档位即 ≥3 所 985），非 985 只能作点缀（如学科 A+ 的行业顶尖 211）。
    - **保底档＝985 与 211 混排**，最低 211（**若学员本科为 985，则保底档须全 985**——见下条层次下限）。
    - **稳妥档与保底档一律不得低于学员本科院校层次**——在 `meta.undergrad_level` 里写学员本科层次（`985` / `211` / `双一流` / `双非`），脚本按 985>211>双一流>双非 逐所比对，低一层即判不合格。例：学员本科 211 → 稳妥/保底不能再放双一流、双非；学员本科 985 → 稳妥/保底只能放 985。
    - 整体框架仍以**软科排名 + 学员本科院校层次**为锚：`rank` 字段填软科位次做梯度自检（冲刺均位次 < 稳妥 < 保底）。
18. **数据真实性铁律（2026-09-19 用户定版）**：**没核实的信息一律不许写进表里**。尤其是这三类高危数据——
    - **保研率 / 推免名额**（全校、学院、专业三级都算）；
    - **排名百分比、绩点线**（"前 10%""GPA3.7+"这类）；
    - **四六级具体分数、雅思托福分数**（"六级 550+"这类）。
    只要**不能百分百验真**（官方公示、招生简章、正式政策文件原文），就**不许写具体数字**，改用定性表述填充：**「排名越靠前越好」「英语成绩越高越好」「核心课首考争取最高分」「有竞赛或科研经历」「以学院当年公示为准」**。
    - ✅ 可以写的具体数字只有三类：① **政策 / 招生简章原文里的硬门槛**（如"平均绩点≥3.00""数学类均分≥75""六级≥425"），写时注明出处条款；② **权威名单类事实**（如"全国保险专业学位研究生教育指导委员会公布的保险专硕授权点名单"含该校）；③ **软科排名位次**等已核实的公开排名。
    - 「录取大致所需条件」（JSON 的 `requirement` 字段）现仅作内部记录/表 1 引用，**PPT 不渲染、Excel 已下线**——可写可不写；要写就一律定性清单，不写排名线与分数。
19. **跨保目标专业的「报考资格」必须先查教育部规定（2026-09-19 新增）**：学员要跨专业保研时，**先确认目标专业对本科专业或工作经验有没有硬性限制**，否则整份定档表会建立在一条走不通的路上。两条最常见也最容易犯错的：
    - **法律（非法学）专硕**：报考前所学专业须为**非法学专业**（法学门类法学类专业〔代码 0301〕毕业生不得报考）；**法律（法学）** 只收法学本科。所以非法学本科跨保法学，只能走 **法律（非法学）**——来源：《全国硕士研究生招生工作管理规定》（当年版）第十六条，可 100% 验真。
    - **须本科毕业后 3 年以上工作经验的专业**：工商管理、公共管理、**旅游管理**、工程管理（125601 / 125602）、教育管理、竞赛组织。应届本科毕业生**不能报考**（同上条款）。典型踩坑："旅游管理本科 → 保研读旅游管理专硕（MTA）"是死路，对口路径只剩学硕或跨考。
    - 这类限制要写进表 1「注意事项」，并让定档表的 `direction` 写**准确的专硕名称**（写「法律（非法学）」，不要笼统写「法学」）。
    - 同时核实目标院校**有没有该专业学位授权点**（以该校当年硕士招生专业目录为准，这是官方可验真来源）。

19e. **抓学员本校 + 本院的推免方案原文，这是政策交付物的全部（2026-09-28 六次定版建立；2026-09-29 八次定版起为唯一的政策交付动作）**：
    - 来源即用户指定的栏目：**https://yz.chsi.com.cn/tm/tjbf/index**（推免信息公开系统 → 推荐办法）。

    - 脚本：`scripts/fetch_school_tuimian_policy.py`

      python "<skill目录>/scripts/fetch_school_tuimian_policy.py" --school "中国地质大学" --pick "武汉" --college "艺术与传媒"

      综合成绩 = **学业成绩 70% + 考核成绩 30%**（不是往年流传的 80/20）；

      CET4≥425（艺术/体育可放宽）；平均学分绩点≥2.80；
      **毕业论文（设计）成绩须达到良好，否则取消推免资格**（校级方案第（七）条，设计类学员的高危项）。
      → 这类硬信息拿到后要回填表 1「保研数据 / 注意事项」，并注明"来源：研招网推免系统 2027 届公示"。
    - **另有一类硬信息藏在学院官网而非研招网（2026-09-29 中北大学仪器与电子学院实测）**：
      学院 2026-08-31 公示的《关于做好2027年推免工作的通知》写明执行**校教〔2025〕9号 + 学院实施办法(2026)版**，
      比网上流传的"2023修订版 / 校发〔2020〕17号"新；申请材料要求**四六级成绩报告单原件及复印件**。
      → 教训：**写"推免依据"前先确认文件版本是不是最新**，别直接抄搜索引擎给的第一份旧办法；
      年份对不上的旧条款要标注版本（如"2023修订版已核实"），并以学院当年公示为准。
    - **技术要点（改脚本前必读）**：① **必须用 curl 发请求**——该站有 TLS/UA 指纹校验，Python urllib 拿不到
      `detailAll` 首页的 taskId（实测 4 次全空，补全请求头也没用），所以脚本所有 HTTP 走 `subprocess` 调 curl；
      ② `detailAll` 是**异步三步**：GET 拿 taskId → `asynProgress.do` 轮询到 `{"state":"SUCCESS"}` →
      POST `detailAll`(taskId+schCode) 取结果页；③ 校级清单在 `schList:`、**院系清单在 `yxsList:`**
      （JSON 内联在 Vue data，形如 `xxx: [...] || []`），正文在 detail 页的 `content:"…"`（富文本含表格）；
      ④ 官方同样**只给 HTML 富文本无 PDF 附件**；交付件原样嵌入该富文本（表格完好），顶部标来源 `detail?zsgsId=…` 链接。
    - **注意：校级与学院两份常常同文**。多数高校的学院方案是转发校级办法 + 同一张加分表（地大武汉 2027 届实测：

    - **注意：院系条目可能只是个跳转链接（2026-09-29 中北大学实测）**。有些学校在研招网只登记一句

      ① `curl -sL -k -A "<UA>" <学院官网URL>` 存成临时 html；
      ② 正文容器通常是 `<div class="v_news_content">`（中北用这个）或 `<div id="vsb_content">`（西安交大等老版），
         用 div 配对扫描截取 innerHTML；
      ③ 调 `fetch_yanzhaowang_policy.write_html(out, title, meta, source_url, body_html)` 复用同一套 A4 打印样式落成 HTML。
    - **附件常带图形验证码，别硬下**：学院官网的附件走 `/system/_content/download.jsp?...&codeValue=xxx`，
      服务端要求图片验证码，**自动下载拿不到**（会返回一个"附件下载"HTML 页伪装成 .pdf，3756 字节、两个附件大小一模一样
      就是这个信号）。此时改用**网页正文里已写明的文件名与条款**做依据，并在表里注明"以学院当年公示为准"，
      不要把未拿到的原件内容写进表。

      且「不低于学员本科层次」判定为相等即通过。本校仍是确定性最高的兜底项，占保底档一席。
    - **冲刺档仍必须全 985、稳妥档仍须 985 过半**——这条与学员本科层次无关，不因本科弱就放宽。
    - 保底档按「985 ＋ 211 ＋ 本校双一流」混排，别全放 211 而丢掉本校。
      实测山西大学那条：兰大(985) / 武理工(211) / 北化工(211) / 山西大学(双一流)，梯度 7<20<63 通过。
    - **不同学校的推免门槛差异极大，绝不能套模板**：中传不设排名线（院内排序＋名额分配），

      写表 1 前必须逐条读该校校级方案原文。
    - **体质测试是常被忽略的硬排除项**：山西大学要求《国家学生体质健康标准》成绩达及格

      这是真实情况不是抓取失败，**如实说明即可，不必去学院官网硬挖**。

19h. **学员本科是「双非」（非 985/211/双一流）＋医药/中医药类专业时的定档口径（2026-09-30 辽宁中医药大学中医学实测）**：
    - `meta.undergrad_level` 写 `"双非"`。**本校一律不得进入任何档位**（铁律 1），包括保底档；
      本校的兜底作用由规划师当面口头说明，不写进表。
    - **中医药领域的两条客观稀缺性，排档前先认下来**：① **211 只有北京中医药大学一所**；
      ② 985 里开中西医结合学科的**只有 7 所**（第四轮：复旦 A-、川大 B+、北大 B、华科 B、
      上交 C+、中山 C、西交 C-）。因此「冲刺全 985 ＋ 稳妥 985 过半」这条要用
      **中西医结合学科等级**来支撑梯度，不能只看综合软科位次——否则上交（软科 4 但学科 C+）

      （如暨南大学中医学院）以尽量贴近「985 与 211 混排」的表述。

## 工作流程

0. **先核实事实（不可跳过）**：用 WebSearch 核实学员院校/学院的下列信息，再动笔写内容——① 学校层次标签与**真实保研率/推免人数**；② 该校**推免硬条件**（是否要求全部课程合格、绩点线、四级/六级线）；③ 院校层次的竞争位次依据（学科评估等级、软科某学科位次，不确定就写区间）；④ 学员所在专业/方向的**最新招生与培养变动**（是否停招、是否本硕一贯制、中外合作办学能否推免、是否有自己的名额）；⑤ 若有中外合作项目，核实**外方学位的硬条件**（语言课等级、GPA 门槛），这常常是学员真正的风险点；⑥ 当年软科中国大学排名（定档节奏要用）。这一步决定整份表的可信度，宁可多花两次搜索。
1. **收集学员信息**。必需：本科院校（含 985/211/双非标签）、专业、当前年级；尽量获取：专业排名/绩点、四六级分数、已有竞赛/科研/实习。信息不全时基于"该院校该专业保研"的通用情况做合理推断并继续，不要卡住等待。
2. **撰写内容（核心：文字必须针对学员定制，禁止照搬模板）**：
   - 结合学员的院校层次、专业学科评估排名、地域、行业去向，分析真实优势与短板（短板的正确位置是表 1「注意事项」第③条，不再单列"待强化项"列）。

### 封面自动改写（第 1 页）

**每回出 PPT，第 1 页封面的院校名和专业名会自动换成本次学员信息**，不需要手动改。数据源优先级：

1. JSON 里的 `cover` 块（推荐，最可控）：
   ```json

   ```
2. 没写 `cover` 时，脚本自动从 `meta.school` / `meta.major` 推断。

改写规则：**逐 run 替换文本、完整保留原有字号/粗体/字体/颜色**（院校名 80pt 粗体、专业名 28pt 粗体，均为微软雅黑，颜色继承主题）。识别顺序：形状名精确指定（`cover.school_box` / `cover.major_box`）→ 占位符文本匹配（`XX大学` / `XX专业`）→ 兜底按字号挑最大的两个文本框。

- 要跳过封面改写：加 `--no-cover`。

### 院校层次铁律自检（生成时强制）

脚本每次生成前会**自动跑一遍院校层次自检**，检查项：

1. 每所国内院校能识别出 **985 / 211 / 双一流 / 中科院特例**（辨认不出即不合格）；
2. **海外兜底行**（`overseas: true`）只能出现在**保底档**、且必须是**最后一行**；若学员信息里没有中外合作/双学位/留学字样，会额外提示确认；
3. **每档至少 2 所**（推荐 4 所），总数至少 6 行；
4. 档位顺序必须是 冲刺→稳妥→保底；
5. **软科排名梯度**：冲刺档均位次应优于保底档。若因学科实力（如本校 A+ 学科综合排名一般但仍是最优选）而有逆转，只提示、不判不合格；
6. **冲刺档必须全部为 985 / 中科院特例**（2026-09-19 新增）：出现 211 即判不合格，提示移到稳妥档；
7. **稳妥档 985 必须过半**（2026-09-19 新增）：4 所档位里 985 少于 3 所即判不合格；
8. **稳妥档与保底档不得低于学员本科层次**（2026-09-19 新增）：以 `meta.undergrad_level` 为基准逐所比对，低一层即判不合格；没写 `undergrad_level` 只提示、不判不合格。

自检不通过会**中止生成**并打印明细，必须回去改数据；确需强行生成加 `--force`。跳过自检加 `--no-tier-check`。

### 定档排序的执行口径（用户 2026-09-17 强调）

定档按"**实际录取难度**"排序，软科综合位次是重要参考但不是唯一标尺：

- **院校层次是硬门槛**：只有 985 / 211 / 双一流 可进任何档（含本校）；**中国科学院大学及中科院各研究所是特例**，可放任意档位。
- **档位先过层次关，再谈学科**：冲刺＝中上 985（优先 C9 / 华五）；稳妥＝大部分 985；保底＝985 + 211 混排，且**都不低于学员本科层次**。院校层次不达标时，宁可换学校也不要靠"学科实力"硬抬档位。
- **学科实力可覆盖综合位次**：环境 A+ 的同济、哈工大放冲刺，环境 B+ 的中山、厦大放稳妥；行业特色校学科 A+ 但软科综合排名靠后，仍可入稳妥档，但**数据里要写明理由**（`fit` 字段里点出学科等级）。
- **本校放保底**（学科最强、确定性最高），不占冲刺名额；本校若为双非则不得入档。
- **梯度自检**靠 `rank` 字段：冲刺档均位次应优于保底档均位次。
- 动笔前**先用 WebSearch 核实当年软科排名**，不要沿用往年或凭记忆的数字。2025 软科主榜参考值（已核实）：清华 1、北大 2、浙大 3、上交 4、复旦 5、南大 6、中科大 7、**武大 8**、华科 9、西交 10、中山 12、哈工大 14、川大 15、人大 17、同济 18、天大 20、**山大 22**、南开 23、厦大 24、湖大 29、重大 34、上财 35、央财 45、苏大 46、贸大 54、**中国海洋大学 56**、中南财 62、西财 65、西北农林 71、辽大 125。
- **定档前先确认"这个学校有没有这个硕士点"**：别凭印象写方向。优先查**教指委 / 学院官网公布的授权点名单**（如全国保险专业学位研究生教育指导委员会公布的 56 所保险专硕授权点），这类名单是 100% 可验真的硬事实，写进表里最安全。

### PPT 版数据：`ppt_tables`（逐字段覆盖）

PPT 页面放不下 Excel 那种长文本，所以 JSON 里可以再加一个 `ppt_tables` 键放精简版。**它是"覆盖块"，不是完整副本**——只写与完整版**不同**的字段，脚本按逐字段合并，其余字段自动沿用完整版：

```json
"ppt_tables": {
  "school_tiers":  [ { "school": "哈工大（环境学院）", "fit": "环境A+，顶尖985" } ]
}
```

> **定档表 PPT 版只有 4 列**：`requirement` 字段写了也不渲染（仅作内部记录 / 表 1 引用）。

- 有 `ppt_tables` → 逐字段盖到完整版上；没有 → 直接用完整版（两表新标准下文案本来就短，多数情况不用写覆盖）。
- **支持两张表各自的覆盖键**：`student_info` / `school_tiers`，都是"按行索引 + 逐字段"覆盖（`overlay()` 实现）。
  `student_info` 的写法是按 rows 下标给 `content`，不覆盖的行写 `{}` 占位：
  ```json
  "student_info": [ { "content": "…压缩版…" }, {}, {}, { "content": "…压缩版…" } ]
  ```
  学员信息表是唯一容易撞 160 字上限的表（尤其「注意事项」三条），先跑 `--dry-run` 看告警行号，再只压那几行。
- `ppt_tables` 是 **PPT 版面适配手段**（不再是"Excel 完整版 vs PPT 精简版"之分）——写与完整版不同的字段（压短校名/优势），其余字段自动沿用。
- `meta` / `cover` 两键可选，只服务于 PPT 封面（见上文「封面自动改写」）。

### PPT 文案的长度标准（照这个写，字号就能停在 12pt）

> 单位是**该单元格的总字数**（不含换行符）。超了只告警不报错，但字号会被压小。

| 表 | 单格字数上限 |
|---|---|
| 学员信息表（4 行） | 表头摘要 **40** / 内容 **160** |
| 冲稳保定档表（4 列） | 适配院校 **12** / 方向 **20** / 优势 **24**（录取条件列已删，不渲染） |
| 主线任务表 | **已全面下线**（2026-09-19，不生成） |

要点：**用 `\n` 显式断行**，比让程序自动折行可靠得多；行动类内容写"动宾短语"，不要写完整句子。

**标准表格版心（2026-10-12 用户定版：以后出 PPT 一律按此排版）**：

## 形态 C：政策解读 HTML（政策文件 → 家长学生分析表）

> 2026-09-19 新增。用户给一份院校推免/保研**政策文件**（PDF 或网页原文），要求出"面向家长和学生的分析表，html 格式"时走这条流程。首例：天津工业大学推免政策（2025-09-08 发布）。

### 何时用 / 何时不用

| 输入 | 走哪条 |
|---|---|
| 学员背景（XX大学XX专业，大二，绩点…） | PPT（唯一形态） |
| 院校政策文件（推免规定 / 保研办法 / 遴选细则） | **形态 C（政策解读 HTML）** |
| 两者都要（先讲政策、再给该学员规划） | 先出形态 C，再出 PPT，两份一起交付 |

### 流程（4 步）

**0. 抽原文**：PDF 先用脚本抽成纯文本，逐条核对，**不要凭印象写分值**。

```bash
python "<skill目录>/scripts/extract_policy_text.py" "XX大学保研政策.pdf" --out policy_text.txt
```

- 依赖 `pip install pypdf`。抽出来字符数 < 200 说明是扫描件，改用 OCR 或去官网/学信网找网页版原文。
- 抽完**通读全文再动笔**，尤其是奖励分条款（分值、门槛、截止时间）和一票否决条款。

**1. 拆成 11 个模块**：政策文件基本都是同一套骨架，按下面这张映射表把原文归位（模块缺省即跳过，但缺核心模块脚本会告警）：

| 模块键 | 标题（默认） | 内容要点 |
|---|---|---|
| `highlights` | 一页速览：四个数字看懂保研 | **4 张数字卡**（num + unit + label + desc）。挑政策里最硬、最容易被忽略的 4 个数字：排名线、英语线、加分上限、成绩计算窗口。 |
| `thresholds` | 资格门槛：谁有资格报名？ | 身份 / 思想品德 / 学习成绩 / 英语 / 能力素质。每行 = 原文要求 + 白话解读 + 性质标签。 |
| `vetoes` | 一票否决 | 政策里"有下列情况之一者不予推荐"那几条。**必须单列成节**，并配一个 `warn` 红框点出杀伤力最大的那条。 |
| `formula` | 综合成绩怎么算 | 公式 + 各组成项的口径与战略含义。加分封顶值、截止日期、排序规则都放这里。 |
| `bonus` | 奖励分全景对照表 | **家长最关心的一张表**。按类别分组（竞赛 / 大创 / 英语 / 科研 / 参军 / 志愿 / 实习 / 荣誉），连续同 `group` 自动纵向合并；同行只首行写 `note` 则该 note 随组合并。 |
| `roadmap` | 行动路线图 | 按学年倒推（大一 / 大二 / 大三 / 大四上），每条写"动作 + 为什么"。 |
| `quota` | 名额是怎么分的？ | 基本名额 / 专项名额 / 支教团 / 总盘子，各行配"家长如何理解"。 |
| `flow` | 推免工作流程 | 政策"工作程序"那几条，压成一两句一步。 |
| `risks` | 红线与风险清单 | 按阶段排：推荐前 / 回避制度 / 成果审核 / 取得资格后 / 最严重情形。 |
| `faq` | 家长最常问的问题 | 6 条左右。挑家长真正会问的（能不能冲、挂科重修行不行、要不要买论文、竞赛是不是越多越好…），**答案要落到政策条款**。 |
| `todos` | 需要向学院确认的问题 | 政策里"由各学院自行制定""参照当年榜单""按教育部当年下达"的部分全部落这里，写明咨询对象。 |

**2. 写数据文件**：按 `assets/policy_sample_data.json` 的结构写到工作目录，命名为 `policy_data_<学校>.json`。

**3. 生成**：

```bash
python "<skill目录>/scripts/build_policy_html.py" policy_data_天津工业大学.json "天津工业大学推免政策_家长学生解读分析表.html"
```

脚本会打印模块清单、表格数、缺失模块告警。**11 个模块齐全 + 表格数与预期一致**才算合格。

**4. 交付**：`present_files` 展示 HTML（同时把 `policy_data_*.json` 一并交付），回复里点出 **3 个最值得当面强调的发现**（通常是一票否决条款、加分规则的坑、待确认事项）。

### 撰写铁律（形态 C）

1. **分值、名次、日期、截止日一律照抄原文**，不做推断、不写"大约"。确实不确定就写区间并标注"以学院当年文件为准"。
2. **每个模块都写 `note` 注明"对应政策第 X 条"**，方便家长回查原文，也方便自己复核。
3. **"首次修读不合格"这类不可补救的条款必须进 `vetoes` 并配红框**，这是家长最容易误解、代价最高的一条（多数人以为重修过了就行）。
4. **奖励分要算"性价比"**，不能只罗列分值。判断维度：分值 ÷ 获取周期 ÷ 门槛 ÷ 确定性。"六级 425 +1 分"通常是最该拿的分，要在表里点出来。
5. **加分规则里的坑要单独成框**（如"同一方面只取一项""与高身份者合作成果不计分""截止 8 月 31 日"），这类规则比分值本身更影响策略。
6. **FAQ 的答案必须落到具体条款**，不写"建议咨询学校"这类废话；确实要问学校的，放 `todos`。
7. **页脚免责声明不能删**，且必须点明"白话解读/难度/性价比/行动路线图为分析意见，不代表学校官方口径"。

19k. **本科是顶尖 985（尤其 C9 / 华五）的学员，定档要按"逐鹿的最终目的地"来排，别只看学校综合位次（2026-10-05 北大信科计算机大一实测）**：
    - **北大 / 清华本科会让 `undergrad_level=985` 触发最严的层次下限**：铁律 17 要求稳妥档、保底档都**不得低于学员本科层次**，
      因此回旋余地只有**985 及以上的院校**——保底档也必须全 985（不能再按"985 与 211 混排"的老套路出牌）。
      实测可行解：冲刺清华 1 / 浙大 3 / 上交 4 / 中科院计算所；稳妥复旦 5 / 本校北大 2 / 南大 6 / 中科大 7；
      保底武大 8 / 华科 9 / 北航 11 / 中大 13（梯度 3 < 5 < 10，自检通过）。
    - **中科院系统的归属优先问"录取难度"，但脚本会让院所进不了稳妥/保底**：脚本原本把"中科院特例"当作低于 985 的层次，
      985 出身的学员一旦把它放进稳妥 / 保底档就会判不合格。**2026-10-05 已修**：`LEVEL_SCORE` 增列 `"中科院特例": 3`（等同 985），
      符合铁律 1「视同顶尖 985，可用于任何档位」。遇到同类报错先看脚本是不是旧版。
    - **计算机 / 电子信息类务必核到的三条硬事实**（都出自院校接收推免的官方通知原文，可写进表）：
      ① **浙大**计算机学院 2027 接收细则：**直博须 CET6≥460**（或 WSK(PETS5) 合格 / 专八 / 雅思 5.5 / 托福 80），
         且明确"**本科毕设成绩须达良好及以上（80 分以上）**，否则取消录取资格"；
      ② **上交计算机学院**（2025 年由计算机系 + 软件学院等重组）接收条件：**本科前六学期专业排名前 20%，C9 高校可放宽**，
         英语 CET6≥425 / 托福 90 / 雅思 6.0；
      ③ **复旦** 2026 年起已组建"**计算与智能创新学院**"（原计算机科学技术学院 + 软件学院 + 大数据研究院等整合），
         别再写"复旦计算机科学技术学院"。

      所以「保研方向」要写清 `081200（直博）` 与 `085400（专硕）` 两条路径，让学生早做"读博 vs 就业"的分岔决策。

19l. **「双一流」标签不能从学科实力反推；储能 / 新能源类学员要按「无独立一级学科」处理（2026-10-11 南京工业大学储能大一实测）**：
    - **⓪ 先查教育部《第二轮双一流建设高校及建设学科名单》（147 所）再定 `meta.undergrad_level`**，不要因为"该校某学科评估 A"就默认它是双一流。实测反例：**南京工业大学化学工程与技术第四轮评估 A（与清华、浙大、北化、大工同档），但不在 147 所名单内，是双非**（江苏省 16 所双一流不含它）。同类还有浙江工业大学（化工 A-）等。层次判错整份档位口径就跑偏：双非 → **本校不得入任何档位**、保底最低 211。
    - **校级方案写"占比由各学院制定"时，必须抓到学院细则才能拿到真实比例**。南工大 2027 校级方案只给区间「学业成绩占比不低于 70%、不高于 85%」，而**能源科学与工程学院自定为 70% / 30%**（旧年份校级口径是 85% / 15%）。照抄旧年份校级比例会写错——这正是铁律 19e「先确认版本」的典型坑。

    - **储能科学与工程（本科 080504T，能源动力类）在研究生阶段没有独立的一级学科**。对口升学口径只有：**080700 动力工程及工程热物理 / 080500 材料科学与工程 / 081700 化学工程与技术 / 085800 能源动力（专硕）/ 085600 材料与化工（专硕）/ 080800 电气工程**；华北电力大学等校自设交叉学科 **0807J1 储能科学与工程**（可 100% 验真）。定档 `direction` 按目标院校实际授权学科写，不要笼统写"储能"。
    - **南工大储能挂靠「能源科学与工程学院」**（不是材料 / 化工 / 电气学院），核心课：电化学原理、电化学储能原理及器件、工程热力学、储热原理与应用、机械储能、储能系统安全管理。

19m. **院系条目跳转目标已死时，政策交付走「校级 ＋ 待确认清单」两段式（2026-10-11 河南师范大学软件学院实测）**：
    - 症状：`fetch_school_tuimian_policy.py --college <院名>` 生成物只有 **3～4 KB、正文 2 行**，内容是「详见教务处官网发布的《各学院（部）推免工作实施细则汇总》（<URL>）」。跟进去后该教务处页返回 **HTTP 410「无效的文章参数！(02)」**（同目录 `.htm` 变体则 301 到 "htm file not found"）——**学院细则盖章原文确实拿不到，不是脚本 bug**。
    - **不要留空壳交付**。正确做法（本次实测）：
      ① **读透校级原文**——院系细则的硬条件基本都在校级方案里，且校级普遍写明「学院细则推荐条件**不得低于**学校规定」，所以校级条款对学员**直接成立**，可放心写进表 1；
      ② 用 `fetch_yanzhaowang_policy.write_html(out, title, meta, source_url, body_html)` 手工重写该院系 HTML，结构固定四段：**① 原文获取状态说明（写明跳转链、HTTP 码）② 校级已核实硬条件表（逐条注明条款号）③ 需学院确认清单（序号/事项/为什么重要/咨询对象）④ 相关公开信息**。文件体积会从 3 KB 涨到 ~8 KB，内容立刻可用；
      ③ 院系是「一体两牌」时（河师大软件学院 ↔ 计算机与信息工程学院），**同一份说明写进两个文件名**即可，不必分两版。
    - **双非师范类院校的校级口径（河师大 师大教〔2024〕2号，2026-09-03 公示，可 100% 验真）**：

## 脚本判定模型（改排版看这里）

`scripts/build_ppt_slides.py` 顶部常量区：`HEADER_BG/FIRSTCOL_BG/BORDER_COLOR`（主题色）、`LINE_FACTOR`（行距）、`CELL_PAD`（上下留白）、`WIDTH_SAFETY/HEIGHT_SAFETY`（估算余量）、`SPECS`（三张表的列名、列宽权重、**列宽上下限 `min_px`/`max_px`**、字数上限、页面匹配关键词、是否合并首列、哪些列居中）。

- 列宽：`allocate_widths()` 按"内容长度 + 权重"分配，再用 `min_px` / `max_px` 夹住并迭代归一化——`min_px` 防标签列被挤成竖条，`max_px` 防长文本列吃掉整行（两列表很容易变成 1:1 五五开，就是没夹 `max_px` 的后果）。
- **标准版心（2026-10-12 用户定版）**：`compute_box()` 一律返回标准版心，不再看占位截图位置。左缘 = 导航右缘 + `STD_GAP_AFTER_NAV`（0.43in，无导航时按 `STD_LEFT_RATIO`=0.2213 取页宽比例），顶部 = 页高 × `STD_TOP_RATIO`（0.1627，避开页标题），右距 `STD_RIGHT_MARGIN`（0.33in）、底距 `STD_BOTTOM_MARGIN`（0.56in）；16:9 下即 (2.95, 1.22)in / 10.05 × 5.72in。**改排版只改这几个常量**，不要退回"跟随截图"的老逻辑。
- 字号搜索：从 `--max-font`（默认 12）以 0.5pt 步进往下试，取第一个能让总行高 ≤ 版心高度的字号；若连 `--min-font` 都装不下，会打印 `⚠溢出` 并告警，此时应回去精简 JSON 文案而不是继续压字号。
- 空内容页识别：`content_hole_slides()` 判定从严——无图片、无表格，且内容区（left ≥ 15% 页宽）里只有恰好 1 个短文本框。放宽阈值会误删有内容的页，**不要随意调**。

打包时整目录复制即可，无需安装依赖声明以外的任何东西：

```bash

```

同事拿到后只需三样：这份 skill 目录 + 自己的 UTF-8 编码 `student_data_xxx.json` + 自己的 PPT。注意：

- **PPT 越简单越稳**：脚本按"标题关键词"定位两张表的位置，若 PPT 里小节标题不含"学员信息/定档"等字眼，就用 `--slides` 指定页码。

## 结果验证（不改 PPT 的检查办法）

```bash

from pptx import Presentation
prs = Presentation(r"输出.pptx")
for i, s in enumerate(prs.slides, 1):
    for sh in s.shapes:
        if sh.has_table:
            t = sh.table
            spans = [(r, int(t.cell(r, 0)._tc.get("rowSpan") or 1)) for r in range(len(t.rows))
                     if (t.cell(r, 0)._tc.get("rowSpan") or "1") != "1"]
            print(i, f"{len(t.rows)}x{len(t.columns)}",
                  "width=%.2fin" % (sh.width/914400),
                  "height=%.2fin" % (sh.height/914400),
                  "right=%.2fin" % ((sh.left+sh.width)/914400),
                  "bottom=%.2fin" % ((sh.top+sh.height)/914400),
                  "首列合并(行,跨行)=", spans,
                  "|", t.cell(0, 0).text, "|", t.cell(1, 1).text[:20])
PY
```

检查点：① **只有两张表**（2026-09-19 起主线任务表全面下线）且行列数与预期一致（学员信息 **5×2**——2026-09-19 起删掉「院校定位」行、定档 13×4——定档表 2026-09-19 起已删掉录取条件列）；② 定档表首列有 3 段纵向合并，每段 4 行；③ `right/left` 不超页宽、`bottom` 不超页高；④ 表内文字用的是预期字号（`run.font.size.pt`）且字体名为「微软雅黑」；⑤ 内置模板输出 **26 页**（不是 27）。

## 形态 C 结果验证（HTML 怎么验）

环境渲染受限时，用文本方式核验结构，**不要靠肉眼看**：

```bash
python - <<'PY'
import re
s = open(r"输出.html", encoding="utf-8").read()
print("h2 节数:", len(re.findall(r"<h2>", s)), "| table 数:", s.count("<table>"))
for m in re.finditer(r"<table>.*?</table>", s, re.S):
    t = m.group(0); body = t[t.find("<tbody>"):]
    rows = re.findall(r"<tr>(.*?)</tr>", body, re.S)
    cols = [len(re.findall(r"<td", r)) for r in rows]
    print("表: 行数=%d 每行 td 数=%s" % (len(rows), cols))
PY
```

检查点：① 节数与表格数符合预期（标准 11 节 / 7 表）；② **奖励分表每行 td 数 + 上方 rowspan 覆盖 = 5 列**（首行 5、被合并行 3 是正常形态，若出现 4 或 6 说明 group 不连续或 note 错位）；③ `<b>` 标签成对、无残留占位符；④ 用浏览器打开确认合并单元格没有错位（本机无 Office/LibreOffice，渲染截图做不到，需如实告知用户自行打开确认）。
