# 保研客户聊单教练

把本机微信聊天记录变成一张**每日聊单作战图**：谁该跟、卡在哪、说什么。

**这是一套「只读 + 出稿」系统**：AI 读你的聊天、算优先级、写建议话术；**发送永远由你本人操作**。

---

## 一、先看这一节：环境与前置

所有路径集中在 **`config.json`**（本技能根目录），换机器只改这里。

> 🆕 **首次使用**：先读根目录的 **`INSTALL.md`**，按它填 `config.json`、装依赖、抓密钥，5～10 分钟可跑通。
> 本包已做隐私清洗，**不含任何真实客户数据**——话术库与复盘报告要由你用自己的聊天记录生成（见第四节）。

| 项 | 说明 |
| --- | --- |
| `key_file` | 微信数据库密钥（64 位 hex），抓一次长期有效，不需要重启微信、不需要重新扫码 |
| `data_root` | 微信数据目录，默认 `C:/Users/<你的用户名>/xwechat_files` |
| `work_dir` | 数据落盘目录（`live/` 增量、`成交客户原始记录/`、`日报/`） |
| `export_script` | 复用 `wechat-chat-export` 技能的 `export_all.py`（解密 + 导出） |
| `cadence_days` | 三类客户的跟进节奏阈值（闪电单 2 / 常规 4 / 长线 7 天） |

**依赖**：一个装了 **pycryptodome / zstandard** 的 Python 解释器（路径写进 `config.json` 的 `python`）。
`wechat-chat-export` 技能需在位（提供 `export_chat.py` 的解密能力）。

**使用前提**：微信在本机**已登录且保持运行**（数据库才会更新）。密钥失效时重跑 `wechat-chat-export/scripts/capture_key.py`。

> 下面所有命令用 `PY` 指代上面那个解释器，`SK` 指代 `~/.workbuddy/skills/baoyan-deal-chat/scripts`，
> `WORK` 指代 `config.json` 里的 `work_dir`（数据落盘目录）。三个变量都在此定义，后文不再重复解释。

## 二、工作流 A：每日聊单（最常用，10 分钟）

### 0) 先读客户档案卡（2026-10-13 新增，防失忆第一动作）

卡片位置：`<work_dir>/客户档案/<客户名>.md`（work_dir 见 config.json；目录不存在就建）。

**用户点名了某个客户（或贴了截图）时，第一件事是读卡，不是跑脚本。** 卡里存着：库外消息（手机端往来，PC 库滞后部分）、关键情报、阶段/风险判定、我出过的稿、待办与分支。没有卡就跳过这步，出完稿后按 4.5 建卡。

> 为什么要有卡：实测（2026-10-13）用户在**手机端**聊单，PC 微信库滞后近一天——用户说「我昨天回过妈妈了」，`copilot.py` 里根本没有那段对话。**库不是真相，卡+截图才是。** 不看卡就出稿 = 让用户重复劳动 + 判断错误。

### 1) 刷新数据（每天第一次用必跑）
```bash
$PY $SK/refresh.py                  # 增量导出最近 60 天单聊 -> live/
$PY $SK/refresh.py --with-deals     # 另需刷新成交客户全量名单时（较慢，每周一次即可）
```
刷新会重建 `live/`，把最近 60 天有互动的会话**连同其完整历史**导出（一次解密，约 40 秒）。

### 2) 打开工作台：今天该先跟谁
```bash
$PY $SK/pipeline.py                 # 控制台看优先级
$PY $SK/pipeline.py --md "$WORK/日报/聊单工作台_$(date +%F).md"
```
输出四块：
- **在跟线索**（客户池，按优先级排序：成交信号 + 风险 + 超节奏 + 阶段推进度）
- **今日必做 Top 8**（附建议动作）
- **存量老客户**（续费/转介绍/交付关怀）
- **渠道·同行**（已自动剔除，不占客户池）

> ⚠️ **口径陷阱（实测踩过，必须知道）**：
> ① **只有控制台版和 `--md` 版**的「在跟线索」按 `segment == "客户"` 过滤过。
> **`--json` 是全分层原样输出**——「XX 老师」「XX 总」「XX 助手」这类渠道/同行/机器人会被算到 130 分以上排在最前。
> 要拿结构化数据时**必须自己再过滤一遍** `segment == "客户"`，否则交付物前排全是同行。
> ② 「存量老客户」只纳入**有近期互动**的成交客户（实测几十个成交客户里只进个位数）。
> **想扫全量老客户**就补一步：`$PY $SK/copilot.py --list` 取全部成交客户 → 对静默天数短的逐个 `$PY $SK/copilot.py "<名字>" --tail 20` 快扫。
> 真实的高等级风险常在老客户池，不补这一步会漏。

### 3) 打开单客户档案：他卡在哪、该说哪一节
```bash
$PY $SK/copilot.py 张同学            # 模糊匹配备注/昵称
$PY $SK/copilot.py 张同学 --tail 40  # 多看些原文
$PY $SK/copilot.py --list            # 列出全部可匹配客户
$PY $SK/copilot.py 张同学 --json     # 结构化，供后续处理
```
档案给出：**身份分层 / 你的聊单笔记 / 关系概览 / 当前阶段（推断）/ 成交信号 / 风险预警 / 跟进节奏 / 该翻话术库哪几节 / 最近对话原文**。

### 3.5) 用户没说跟谁 → 先定位，再出稿（**不许自己挑一个就写**）
用户只丢一句「客户说太贵了怎么回」这类**没给客户名**的需求时，按这个顺序走，四步都不要跳：

1. 扫 `live/` 全部会话，找**客户侧**的目标信号（价格异议：贵/价格/优惠/预算；待回：问句未答）。按最后互动时间倒排。
2. 剔掉 `segment != "客户"` 的（渠道·同行 / 内部同事 / 机器人）。
3. 🔴 **CHECKPOINT**：挑 **2~3 个候选**，连**「为什么是他」**（命中哪句话、哪一天）一起**发回用户确认**——**停下等答复，不要自己挑一个直接出稿**。
4. 用户确认后再走第 4 步出话术。

> 反面教材：用户问「客户说太贵了」，直接按通用模板写一大段——**既不知道是谁、也不知道他最后一句说了什么**，等于白写。

### 3.6) 截图优先原则（2026-10-13 新增，硬规则）

用户消息里带 `@image` / `<image_local_path>` 时：

1. **先 Read 截图**，把它当作该客户状态的**最新事实源**——优先级高于 `live/` 库。
2. 截图里出现库中没有的消息（手机端发出/接收）→ **先把这些消息补写进客户档案卡的「库外消息」表**，再判定阶段、再出稿。
3. **出稿前自检一句**：「用户/客户最后一条消息，我是从卡/截图里看到的，还是从旧库里看到的？」旧库看到的，回到第 1 步。
4. 绝不说「你还没回他」这类话，除非截图和卡里都确认没有回复。

### 4) 出话术（AI 的活，不是脚本的活）
拿到档案后，AI 按这个顺序写：
1. **读最近 20~40 条原文**，弄清客户此刻的真实处境（别只看信号标签）
2. **定位阶段**（S1–S6 或 P1–P3）→ 翻 `references/03-阶段关卡与成交链.md` 找对应关卡动作
3. **匹配异议类型** → 翻 `references/01-成交话术库.md` 找**你自己验证有效的原话**
4. **改写**：保留句式与心法，替换成这个客户的具体信息（院校、年级、诉求）
5. **给 2~3 条，标注该说哪句、为什么**
6. 🛑 **STOP**：出稿即止。**发送由你本人操作**——AI 到这里必须停，不代发、不自动回复。

### 4.5) 写回客户档案卡（2026-10-13 新增，每次出稿后必做）

出完稿，用 Write/Edit 更新 `<work_dir>/客户档案/<客户名>.md`（没有就新建），至少记五样：

1. **库外消息**：截图/口述里、`live/` 库中没有的最新往来（时间+谁+内容原文）
2. **关键情报**：本轮新拿到的事实（竞品在聊/拍板权转移/价格敏感…）
3. **阶段与风险**：S0–S6 / P1–P3、★几、节奏是否超期
4. **出稿记录**：我给了什么策略、用户实际发了没有（截图能确认的要确认）
5. **待办与分支**：下次动作+具体时间、触发式分支（问价→怎么回/点名竞品→怎么回）

卡片是跨会话记忆的唯一真相源；下次开工按第 0 步先读它。

### 5) 收工自检
- 今天推进了谁？各拿到什么新证据？
- 谁还没推、明天优先？
- 有没有风险要处理（抵触/竞品；**退费类按用户要求不再纳入**，见第五节第 6 条）？

## 三、工作流 B：新客户从 0 到签约

按六步链走，**每步有退出标准，没拿到证据不算推进**（详见 `references/03`）：

破冰建档 → 诊断定档 → 方案报价 → 破异议 → 逼单 → 签约交付

两个最容易漏的动作：
- **开口要合同**：数据里成交客户 42% 发过 e签宝、41% 发过甲方信息表；不敢开口，单子停在门口。
- **约定下次时间**：客户说「跟家里商量」时，必须拿到一个具体时间点，否则这单会静默掉。

## 四、工作流 C：周期性复盘（每月/每季，给话术库补料）

```bash
$PY $SK/parse_labels.py                       # 成交名单（微信「已成交」标签）-> outbox/
$PY $SK/refresh.py --with-deals               # 重导成交客户全量历史
$PY $SK/analysis/deal_review.py               # 画像 / 节奏 / 证据覆盖 / 跨会话复用话术
$PY $SK/analysis/objection_mine.py            # 异议→应答配对 / 逼单话术 / 风险逆转话术
```

> 📌 **本包未附带复盘报告**：`02-成交客户共性报告.html` 是**用真实客户数据生成的**，涉及隐私，未随包分发。
> 你跑完上面两条分析脚本后，让 AI 按 `analysis/deal_review.py` 的产出**自己生成一份同名的 HTML 报告**放进 `references/`（深红主题、可打印，结构照 `INSTALL.md` 里的模板）。
> 同理，`references/01-成交话术库.md` 在本包里是**空骨架 + 方法**，跑完 `objection_mine.py` 后回填你自己验证有效的原话。

新挖到的好话术，🔴 **CHECKPOINT**：**先把新话术给用户过目，确认后再回写进** `references/01-成交话术库.md`（这是资产，越用越厚）。

## 四·五、工作流 D：置顶客户回访（用户点名"置顶客户"时）

微信置顶**不落库**（见排障表），所以顺序是：

1. 🔴 **CHECKPOINT** **拿置顶名单**：截微信窗口 → `scripts/ocr_screen.ps1` → 读会话列表顶部条目 → 取其中的**客户**（剔掉群/渠道/内部）→ **把名单发回给用户确认，停下等确认再往下**（深色模式下无法自动判定边界）。
2. **先增量导出**（关键）：`live/` 可能是几小时前的，漏掉当天新消息会直接写错判断。用排障表里的 `export_all.py --out-dir <工作目录>/_fresh`（避开被拦的 `safe_delete`）。
3. **逐个跑档**：`$PY $SK/copilot.py "<客户名>" --tail 40`，看阶段/信号/风险/最近原话。
4. **复核 ★3**（误报率约一半）：见第五节表格，逐条翻最近 20 条原文，标 CONFIRMED / FALSE POSITIVE。
5. **出稿**：每人给「卡点 + 今天的具体动作 + 2~3 条可复制话术（附为什么 + 出处章节）」，按「紧迫度 × 成交概率」排序；**另外把置顶之外的高成交概率线索单列一节**（**退费/维权类客户按用户要求不再纳入**，见第五节第 6 条）——高价值机会常藏在老客户池里。
6. **产物形态**：深红主题单文件 HTML（可打印），存桌面，文件名 `微信置顶客户回访作战图.html`。

> **必做自检**：出现「约会议 / 约语音」这类动作前，先翻原文确认**这一步是不是已经做过了**——实测踩过：语音昨晚已通、会上周已开，按"待约"写就全错。

## 五、判定口径（**必须遵守，别自己发明**）

### 1. 谁是「成交客户」
**只认微信通讯录的「已成交」标签**（`contact.db` → `contact_label`，`label_id=42`；
联系人标签在其 `contact.extra_buffer` 的 **field 30**，逗号分隔的标签 ID）。
❌ **绝不要**用「发过合同/发过收款账户」这类行为去猜成交——只能猜到个位数，会严重低估（实测：行为口径只有个位数，标签口径是它的十几倍，数量级差一档——你跑出来的数以你自己为准）。

### 2. 身份分层（`wxlib.segment`，三层判断：名字 → 标签 → 对话内容）
- **客户**：学生/家长（默认）
- **渠道·同行**：名字含「老师/规划师」、带渠道标签（`wxlib.CHANNEL_LABELS` 里你自己填的那些），
  **或对话里我平时管他叫「X老师」** → 走转介绍/对账，**不进客户池**
- **内部同事**：对方话语里全是内部运营词（师资群/客诉/加急/接手/来源：/已转…），
  或名字写在 `config.json` 的 `internal_names` 里 → 剔除
- **机器人**：名称含 bot/助手/服务号/元宝/deepseek… → 直接剔除

> **这三个分层是这套工具最容易漏的地方**：微信里混着大量同行老师、渠道协作方、内部同事和 AI 助手，
> 不筛掉它们，工作台前排全是「XX 老师」「XX 总」「XX 助手」这类名字。
> 判断规则在 `wxlib.py` 的 `BOT_KW` / `CHANNEL_LABELS` / `PEER_KW` / `INTERNAL_KW`，**发现漏网就往里加词**，
> 或把名字钉进 `config.json` 的 `internal_names`。

### 3. 阶段
- **未成交**：S0 新线索 → S1 破冰建档 → S2 诊断定档 → S3 方案报价 → S4 破异议 → S5 逼单 → S6 签约交付
- **已成交**：P3 风险处置 / P2 交付期 / P1 维护期（**不要给老客户套销售漏斗**）
- 脚本给的是**规则推断**，拿关键词命中算的，**必须用原文复核**；标注为「推断」

### 4. 风险等级
★3 高风险（退费/投诉、学生抵触、决策人缺位+逼单）＞ ★2 中（价格受阻、竞品比价）＞ ★1 低（拖延、静默）

### 5. 脚本结论复核（**必做，误报率约一半**）
实测（2026-10-11）复核 9 个客户，**5 个脚本结论被原文推翻**。以下三类误报最常见，看到就要翻原文：

| 脚本标记 | 误报成因 | 复核方法 |
| --- | --- | --- |
| **★3 退费/投诉** | 客户**转发的微信系统安全提示**里含「我要投诉」（「对方账号安全性未知…我要投诉」） | 原文里能定位到这条**系统消息**即误报 |
| **★3 明确放弃** | 命中的是**很久以前的某次单项异议**（如半年前「暂时先不考虑论文了」），客户后来仍在主动联系 | 只看**最近 20 条**有无放弃表述；有主动来电/主动提问即误报 |
| **S6 签约交付** | 「身份证」「甲方」等词误命中 | 核对有无 e签宝/甲方信息表/对公账户的**实际动作**，14 条以内的小会话基本都是误报 |

**两条硬规则（2026-10-11 实测确认，照做）**

1. **判定一律只看最近 20 条**。`scan_risks` **不带时间窗口**——它扫会话全量关键词，所以「半年前说过一次贵」也会被它算成今天的高风险。
   20 条以内的会话（尤其 < 14 条）**基本全是误报，直接降级 ★1**，别往上排。
2. **老客户池的 ★3 必须逐条翻原文**。`post_sale_stage` 是**关键词命中即判**，处于正常交付期的老客户常被误标 ★3 退费/投诉（实测踩过）。
   脚本结论只能当**候选**，原文才是判据——抄脚本结论直接交付，等于把误报当警报发出去。

**反向也要注意**：确有「明确放弃」属实时（客户近期明确说「先不考虑了」），**当天不要催**，转内容型长线，一周后只投喂价值。

> **扫池提醒**：日报的客户池**必须连「存量老客户」一起扫**。高价值线索常藏在老客户池里，不在「今日必做 Top 8」中。
> ⚠️ **但退费类客户不再纳入（2026-10-12 用户明确要求）**：命中退费/维权/投诉的直接剔除，不翻原文、不写进日报；只保留可缴费、可成交、可转介绍的客户。详见下方第 6 条。

### 6. 退费客户的处置（2026-10-12 用户明确要求，最高优先级）

**用户原话："以后退费的不用管了，只管可以缴费的。"**

- 日报、今日必做、置顶回访作战图等**一切交付物中，不再纳入退费 / 维权 / 投诉类客户**——不督办、不出话术、不占优先级、不单独列节。
- 脚本（`scan_risks` / `post_sale_stage`）命中的退费类 ★3 只当**剔除标记**用，**不翻原文、不写进日报**。
- 老客户池照扫（防漏高价值线索），但命中退费/维权/投诉的**直接剔除，只保留可缴费、可成交、可转介绍的客户**。
- 例外：只有用户**当次明确点名**某个退费客户，才为他单独出稿。

## 六、话术生成规则（AI 必须遵守）

1. **只用真实原话改写**：语料来自 `references/01-成交话术库.md`，那是你自己成交单里用过的话。
   **不要凭空造话术**，也不要拿通用销售模板糊上去。
2. **贴合上下文**：必须回应客户**最后那几句**的具体内容，不能答非所问。
3. **不编数字**：金额、排名、成功率、院校层次、优惠幅度 —— **没核实的一律不写**。
   拿不准就改定性表述（「以当年公示为准」「越高越好」）。
4. **价格异议**：守价 → 帮你向领导申请 → 给「争取来的」优惠。**优惠是你替客户争取的战果，不是降价。**
5. **不承诺做不到的**：不替教务/学员承诺具体结果；合同条款只引用已确认模板。
6. **输出格式**：给 2~3 条可直接复制的备选，每条附一句「为什么这么说」+ 出处章节。
7. **引用原话先核对档位**：话术库里的话是**在特定单子上说的**，金额和权限都绑着那一单的档位。
   例：`01-成交话术库.md` 2.1③ 的「整体优惠 7000」是**9w 全流程**档的语境，客户报的是 1.3w / 3w 档时**直接套用就是编数字**。
   拿不准档位就改定性表述：「以实际能批下来的权限为准」。

**这 5 处不是「建议确认」，是「停下来等答复」。没等到答复不许往下走。**

| # | 位置 | 触发条件 | 必须做的动作 |

## 八、铁律

1. 🛑 **全程只读（最高优先级，无例外）**：绝不向微信发送任何消息，绝不自动回复。**出稿，由你发。**
2. **数据不出本机**：聊天记录、密钥、分析产物只落本地，不外发、不上传。
3. **成交判定只认标签**，不用行为猜。
4. **已成交 ≠ 留存**：`is_refunded()` 会标出疑似退费客户，走修复不收新单。**另：用户 2026-10-12 明确要求"退费的不用管了，只管可以缴费的"——退费/维权/投诉类客户一律从交付物中剔除**（第五节第 6 条）。
5. **缺信息不编**：脚本报的是推断，AI 出的是建议，**最终判断在你看完原文之后**。

## 九、排障（三段式：先试一线修复，不行再走兜底）

> 三列读法：**症状**（你看到什么）→ **一线修复**（先试这个）→ **仍失败兜底**（还不行才用，一般是往上一层降级）。

| 症状 | 一线修复 | 仍失败兜底 |
| --- | --- | --- |
| `密钥未能解锁任何账号` | 换了账号或密钥过期 → 跑 `wechat-chat-export/scripts/capture_key.py` 重捕 | 确认微信**当前已登录且保持运行**再重捕；仍失败就核对 `config.json` 的 `key_file` 是否指向新抓到的 key.txt |
| 找不到 `all_messages.jsonl`，或 `live/` 是空的 | **先核对真实产物形态**：`live/` 是**每个会话一个 `.txt`**（不是单个 jsonl）。目录为空 = 还没导出 → 跑 `refresh.py` | 目录里明明有 `.txt` 却读不到 → `config.json` 的 `datasets` 指错了，用 `copilot.py --list` 反查它实际读的是哪个目录 |
| 工作台里客户数很少 | 微信没在运行（数据库不更新）→ 打开微信并保持登录；或 `live_days` 设太小 → 调大 | 还是少 → 手动跑 `export_all.py` 导一版到 `_fresh`，确认数据源本身有没有内容 |
| 客户名匹配到多个 | `copilot.py --list` 找全名，或直接传 wxid | 名字里带 emoji / 空格导致匹配不上 → 把 `--list` 里的原名整串复制过来 |
| 老客户显示成「新线索」 | 该联系人没打「已成交」标签 → 在微信里补标签 | 标签改不了 → 看 `remark/description` 是否含「成交」，或把 wxid 钉进 `config.json` |
| 渠道/同行混进客户池 | 名字里没有「老师/规划师」等特征，也没在对话里被我称「X老师」 | 往 `wxlib.CHANNEL_LABELS` / `PEER_KW` / `BOT_KW` / `INTERNAL_KW` 补关键词，或把名字加到 `config.json` 的 `internal_names` |
| 工作台前排全是「XX老师」 | 分层失效（一般是改了名字或新加了联系人） | 同上；跑 `copilot.py --list` 逐个人核对分层结果 |
| 明明没事却被标「★3 退费/投诉」 | **误报**：客户转发的微信系统安全提示里含「我要投诉」被关键词命中 → 翻原文复核（只看近 20 条） | 要压掉就往 `wxlib.py` 的风险词逻辑里加排除（系统消息 / 转发消息不计）；误报在原文里能找到「对方账号安全性未知…我要投诉」这类**系统消息** |
| 脚本报 `head/tail/wc/mkdir/ls: command not found` | 本机 bash 缺 GNU coreutils（只读环境常见）→ **别用管道做二次处理** | 改成 `$PY $SK/pipeline.py > "$WORK/_out.txt" 2>&1`，再用 Read 工具读文件 |
| `refresh.py` 报 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 后中止 | 🛑 **不要删旧数据**。`live/` 有 300+ 文件，`safe_clean()` 要 rmtree 被安全钩子拦住。**一线修复（2026-10-12 实测有效，最简单）**：`mv live live_backup_<日期>` 把旧目录**改名保留**（不是删），再重跑 `refresh.py` 重建 `live/`——`config.json` 无需改动，下游 pipeline/copilot 全部照常 | 仍失败 → 调上游导出器导到新目录：`"$PY" "$SK/../wechat-chat-export/scripts/export_all.py" --data-root <data_root> --key-file <key_file> --out-dir <WORK>/_fresh --kinds 单聊 --since-days 60 --min-messages 2`，再把 `_fresh` 加进 `config.json` 的 `datasets`（`load_chats` 按 `(wxid,ts,is_self,content[:60])` 去重，重复不会串数据）；确实要删就先取得用户明确同意 |
| 想扫高危退费/投诉单，但客户静默已超 21 天 | ⚠️ **静默 > `cold_silence_days`(21) 的客户会被日常池整体过滤掉**，不进「今日必做 Top 8」，也不是「存量老客户」（那个只收有近期互动的）→ **可成交线索会整个漏掉**（实测：某 211 文科高意向单就藏在这里） | 每天补一步全量扫描：`cd <live> && grep -l "退费\|违约\|投诉\|维权" *.txt`（也可加「规避法律责任/套现」扫自身合规风险）。**但注意：命中退费/投诉的客户按用户 2026-10-12 要求直接剔除，不写进日报**；剩下的逐个 `copilot.py <名字> --tail 20` 复核。用户当次点名要某个退费客户时才为他单独出稿 |
| 想知道「谁被置顶了」 | 微信**置顶状态不落库**（`SessionTable` 无 top/pin 字段，`general.db` / MMKV 亦无）→ 只能屏幕 OCR：截微信窗口 → `scripts/ocr_screen.ps1` → 取会话列表顶部条目 → 与 `copilot.py --list` 对名 | 深色模式下置顶行无颜色差异、判不出边界 → **直接把候选名单发给用户确认**，别硬猜 |
| 截图读微信，截出来是别的窗口 / 一片空白 | ① 模型读不了 png（Read 返回 "current model does not support images"）→ 一切视觉识别走 OCR，**不要声称"我看到了"**；② `PrintWindow` 对隐藏的 Qt 窗口返回空白 → 先 `ShowWindow(SW_RESTORE)` + `AttachThreadInput` 抢前台再截 | ③ BitBlt 用的是窗口 DC、被遮挡时拿到的是遮挡物 → 改从**桌面 DC**（`GetWindowDC(GetDesktopWindow())`）按窗口 rect 裁剪；仍失败就放弃截图路线，改问用户 |
| 想滚动微信会话列表看更多置顶 | 会话列表不响应 `mouse_event` 滚轮（发了也不动）→ 一次只能看 ~9 行 | **直接问用户要完整置顶名单**，别硬怼滚动 |
| 库里消息比用户截图旧（用户说「我昨天回过她了」，`copilot.py` 里没有） | **手机端滞后**：用户在手机端聊单，PC 微信数据库不同步 → **以截图/用户口述为最新事实源**，先把库外消息补进 `客户档案/` 卡片再出稿；同时保持 PC 微信在线等它同步 | 仍不同步就接受卡片机制——卡片是跨会话唯一真相，`live/` 只作历史背景 |
